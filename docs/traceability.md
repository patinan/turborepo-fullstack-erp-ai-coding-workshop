# Requirements traceability — Release 1

One row per requirement in the release 1 baseline (TOR §7.2: "for each requirement, confirmed acceptance criteria, traceability to the delivered functionality, test results, and evidence of technical review").

- **Acceptance criteria** are defined in `docs/specs/release-1.md`.
- **Depends on** lists clarification register entries (`docs/clarifications.md`). While any of them isn't `Approved`, the affected criteria are blocked for acceptance (TOR §7.3). Entries in **bold** decide whether the whole requirement passes at all, so their rows are marked blocked now. For the other entries, only the criteria tagged with that entry in the spec are blocked.
- **Tests** are the planned locations; update them to the real file and test name when the test is written.
- **Result** is one of `Not run`, `Pass (<date>, <commit>)`, `Fail (<issue>)`, `Blocked`. Update it from the latest CI run or evidence file at each milestone.
- **PRs** lists the merged PRs that delivered or changed the requirement; their reviews are the evidence of technical review.

Test file prefixes used below: `contracts/` = `packages/contracts/src/`, `api/` = `apps/api/src/`, `web/` = `apps/web/src/`, `e2e/` = `apps/e2e/tests/`, `perf/` = `perf/`.
